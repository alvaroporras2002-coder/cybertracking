Qué está incluido

El temario contiene 52 semanas y 364 sesiones. Las semanas 1 a 4 forman el primer bloque con bancos de evaluación y retos desarrollados; las semanas posteriores se pueden consultar y mantienen sus evaluaciones pendientes. El estado exacto se describe en CONTENT_STATUS.md.

La experiencia incluye inicio, ruta, aula, notas, progreso y ajustes. Los videos pueden verse dentro de la página cuando el proveedor permite insertarlos; si no, se conserva el enlace original. La estética combina arte isométrico y efectos fluidos discretos, sin mover el texto de estudio.

Esta guía explica cómo publicar. No se ha creado un repositorio ni se ha desplegado el proyecto automáticamente.

1Coloca los archivos en su lugar

Crea en tu computadora una carpeta llamada cybertrack. Guarda en ella los archivos entregados manteniendo las rutas siguientes. Si recibes archivos individuales, crea sus carpetas antes de guardarlos; no cambies sus nombres.

2Prueba la carpeta antes de subir

La página carga datos y módulos. Por eso, abrir index.html con doble clic no es una prueba fiable. Si tienes Python, abre una terminal dentro de la carpeta y ejecuta:

python -m http.server 8000

Si tu equipo utiliza python3, cambia solo esa palabra. Visita http://localhost:8000. Este paso no publica la página ni necesita que instales dependencias del proyecto.

Antes de continuar, comprueba que abren Inicio, Ruta y una sesión; que el diseño funciona en ventana estrecha; y que una nota se conserva al recargar.

3Sube el contenido al repositorio

  1. En GitHub, crea un repositorio nuevo, por ejemplo cybertrack, o elige uno vacío para este proyecto.
  2. En la página del repositorio, selecciona Add file → Upload files.
  3. Arrastra los archivos de la raíz y las carpetas completas assets, data, tools y tests. Conserva su estructura.
  4. En la vista previa, confirma que index.html está directamente en la raíz y que existe assets/css/styles.css.
  5. Guarda los cambios. Si GitHub solicita una propuesta de cambios, complétala y fusiónala según las reglas del repositorio.

Si el selector de tu navegador no conserva una carpeta, entra en la ruta correcta del repositorio para subir sus archivos, o utiliza GitHub Desktop. No soluciones el problema colocando todos los archivos en la raíz: se romperían las rutas.

Para una primera carga puedes utilizar este mensaje y descripción de commit:

Añadir la plataforma CYBERTRACK

Co-authored-by: Codex <noreply@openai.com>

No subas respaldos personales, evidencias privadas ni contraseñas. La visibilidad y las funciones de publicación disponibles dependen de tu plan y del repositorio.

4Activa GitHub Pages

Con los archivos ya guardados en main, abre Settings → Pages. En la configuración de publicación elige Deploy from a branch, selecciona main y /(root), y guarda.

Utiliza la dirección que GitHub muestre al terminar. En un repositorio de proyecto tendrá una estructura parecida a https://USUARIO.github.io/REPOSITORIO/; no copies esos marcadores como si fueran tu dirección real.

Las rutas del proyecto son relativas para funcionar bajo la carpeta del repositorio. No las cambies por /assets/... o /data/... sin adaptar la aplicación.

Si no aparece el sitio, revisa el resultado de la publicación en las ejecuciones del repositorio. Una carga de archivos completada no significa que la publicación ya haya terminado.

La página publicada está pensada para acceso web. Tus datos de estudio siguen en tu navegador; el alojamiento no agrega sincronización ni una cuenta privada.

5Protege tus registros y actualiza

  • Usa Exportar respaldo completo antes de cambiar de equipo, URL o versión.
  • Comprueba qué incluye la exportación: el respaldo completo contempla evidencias binarias; una exportación ligera puede excluirlas.
  • Guarda el respaldo fuera de la carpeta que subes a GitHub.
  • Computadora y teléfono mantienen estados diferentes. Para trasladar datos, exporta e importa; no se sincronizan automáticamente.
  • No borres almacenamiento para resolver errores. Conserva primero una copia y revisa el mensaje.
  • Para actualizar el código, conserva rutas e IDs del contenido. Verifica la nueva versión antes de reemplazar archivos.

La aplicación es una herramienta personal. Marcar un video confirma tu declaración; no demuestra que lo viste. Los retos comprueban tareas limitadas dentro de la web y no equivalen a una certificación.

Pruebas para una actualización

node --test tests/*.test.mjs
python tools/validate-content.py

No declares una actualización lista hasta revisar sus resultados y comprobar el flujo real de estudio y respaldo.
